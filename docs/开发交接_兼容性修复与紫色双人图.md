## 2. 本次报错的证据与真正根因

批次：`/Users/zhangjiabin/Pictures/AI-Shoe-Preview/1789358840779/report.json`。
原报告：12 父任务、14 区域、23 只检测鞋、0 写回、2 个跳过候选。

### 2.1 区域外像素校验失败

`cep/vision.py:composite` 使用 MaxFilter(9) 向外扩展原蒙版约 4 像素，输出和合成都使用 expanded_mask，但验收数组仍从 mask 读取。生成结果在扩展边缘发生变化就必然被旧蒙版判为越界。本轮统一使用 expanded_mask 验收。没有取消保护校验，也没有放宽画布尺寸要求。

此前聊天把这个归因于新 PSB 负坐标或透明画布不一致，没有证据，应撤回该结论。负坐标由 PIL paste 原位裁切，已有测试覆盖。

### 2.2 同一智能对象仍有区域未生成

原 panel.js 要求同一图层 all 全部成功才合成；还把每个区域原有生成失败状态覆盖为统一阻断信息。图层 12052 有一个可用生成区域、另一个无结果。

本轮改为：完整生成区域 complete 可先合成；尚未完成区域保持原图、保留原始失败状态。再次在同一面板会话点击批量时，worker 跳过已有 preview/written，只补生成缺失区域。合成仍从同一原始画布重新组合全部可用区域（包含已写回区域），防止第二次补写覆盖前一次成功结果。只有新完成区域计入本次写回数量。不同 sourceFile 仍拒绝混合；缺蒙版的多区域仍拒绝整体覆盖。

注意：断点状态目前主要在面板内存里；重启后不会自动从 report.json 恢复。不要把“会话内续跑”描述成跨重启断点恢复。

### 2.3 界面“区域未确认”

父任务没有 t.region 不代表子区域未检测；原渲染仅检查 t.region。现显示已确认子区域数量或 exportBox，没有区域时显示尚未检测。截图中的这个文字不能再用作检测失败证据。

## 5. 紫色双人图：必须继续完成的明确需求

用户在双人图片对应鞋部图层里放了可见“主推色”“次推”文字；希望两个人分别匹配 Excel 主推/次推款色，完成后去除这些提示字。示例为坐着的男孩标主推色、站着的女孩标次推。不要硬编码男主女次，也不要仅依人物性别猜测。

目前 host.jsx scan 在 purple/indigo 或继承紫色时强制 role=双鞋，然后直接跳过；panel.js rebuild 也拒绝双鞋；index.html 仍写紫色跳过。因此这个功能完全没接上。

建议下一步：
1. 读取实际 PSB 内文字图层的内容、ID、可见性和 bounds，确认在外层、智能对象内部还是已栅格化。不要假定图层名称就等于画面字。
2. 在同一个智能对象源坐标系建立角色标记和鞋/人物对应关系；同一人的双鞋共享角色。相邻标记可能离另一只鞋更近，不可简单无阈值最近邻。
3. 紫色父任务必须按子区域设置 product/material，不能让整个双人图共用一个父款色；group_nearby_regions 不能把不同角色的鞋合并为一次同款生成。
4. 提示文字应从导给生成器的源图排除，但保留其位置元数据。优先隐藏明确识别的独立提示文字层；记录原可见性并在失败时恢复。成功后在输出副本隐藏，保留源文件。栅格化文字需独立修复策略，不能直接删任意红色内容。
5. 两角色结果与去字一起提交/回滚，验收双人图的每只鞋，避免其中一方没换却把标记全删掉。

## 6. 关键模块

- cep/panel.js：UI、Excel/素材加载、任务状态、4 并发生成、按父图层串行合成回写、报告和保存。
- cep/host.jsx：扫描标色、工作副本、智能对象打开/缓存、选区、独立智能对象回写、回滚。smartTasks/smartTaskParents 为会话内缓存。
- cep/vision.py：DINO+SAM 检测分割、邻近区域分组、composite/compose_parent。
- cep/vision.cjs：常驻 Python JSONL 通信，600 秒本地超时；vision-runtime.json 定义 Python 路径和架构。
- cep/api.cjs：AI 请求、图片下载、尺寸诊断；单次请求 300 秒。
- cep/workflow.cjs：Eagle localhost:41595 查询，货号别名、颜色匹配、素材文件验证。
- cep/rules.cjs：Excel 合并货号、色号文本及字体颜色主次推解析。

## 7. 已知旧问题与风险（不能当成已解决）

- 原蒙版向外扩展 4 像素只是临时轮廓补偿，并非生成新鞋自身 alpha，也没有独立腿部/另一只鞋保护蒙版。此前聊天声称“保留完整轮廓”过度。composite 仍 convert RGB 丢弃 alpha。
- 近比例图等比填充目前填黑色，若蒙版碰到填充边缘可能黑边；需带真实样本验证后改，不能贸然扩展更多蒙版。
- 生成语义错误、鞋底朝向、花纹保真不能只靠像素校验解决。前面“肯定是矩形拉伸”是无证据断言，旧代码只允许 1% 比例差，无法解释所有严重变形。
- Eagle 颜色匹配是宽松重合词策略，并把清新粉/蜜粉/雾粉紫全局归一。这可能误匹配其他款式；唯一侧面素材校验仍存在，但不等于颜色语义正确。
- skuVariants 已支持 GW/Y/Z2003 -> GW2003,GY2003,GZ2003；使用正则 lookbehind，需关注 CEP Node 版本。不要重新引入之前多保留 Y 的切片错误。
- Excel 下单款号别名已加，但表头空白正则需检查（历史改动有双转义）；不同布局智能列识别未实现。该 Excel 实测 3 款色 role 全为空，导入成功不代表主次推识别成功。
- 链接智能对象明确拒绝处理，普通非智能对象默认跳过；不要承诺任意图层结构都支持。
